# Setting the device up in RaceChrono

## Pairing

1. Power the device. The LED winks once a second while it advertises.
2. In RaceChrono: **Settings -> Other devices -> Add device -> Other Bluetooth LE
   device**.
3. Pick `KartGPS` from the list.
4. Enable it as the **GPS source**. Position, speed, bearing, altitude,
   satellite count and DOP arrive automatically — they use the standard GPS
   characteristics of the DIY API and need no configuration.

The LED goes solid once the app is connected and the receiver has a fix.

## The extra channels

Acceleration, rotation and device status ride on the CAN-Bus characteristic,
which RaceChrono treats as generic sensor data. They have to be declared once,
because only this firmware knows what the bytes mean.

RaceChrono asks for a packet ID and then, per channel, where the value sits
inside the payload and how to scale it. The tables below are the authoritative
layout — they are generated by `lib/kartcore/src/channels.cpp` and pinned by
`test_kartcore`. **Every field is big-endian and two's complement signed unless
stated otherwise.**

For the exact formula syntax in the channel editor, see RaceChrono's own
reference at <https://racechrono.com/support/equations>; the field names in the
editor have changed between app versions, but the offsets and scale factors
below do not.

### Packet 0x100 — Motion, 25 Hz

| Channel | Offset | Size | Signed | Multiplier | Unit |
| --- | --- | --- | --- | --- | --- |
| Longitudinal acceleration | 0 | 2 | yes | 0.001 | g |
| Lateral acceleration | 2 | 2 | yes | 0.001 | g |
| Vertical acceleration | 4 | 2 | yes | 0.001 | g |
| Roll rate | 6 | 2 | yes | 0.1 | deg/s |
| Pitch rate | 8 | 2 | yes | 0.1 | deg/s |
| Yaw rate | 10 | 2 | yes | 0.1 | deg/s |

Sign conventions, after the SET button has zeroed the sensors:

- **Longitudinal** positive forward. Braking reads negative.
- **Lateral** positive to the right. A right-hand corner reads positive.
- **Vertical** positive up, with gravity removed, so a stationary kart reads 0
  and a kerb strike shows as a spike.
- **Yaw rate** positive turning right.

Values saturate at the ends of the int16 range rather than wrapping, so a hit
beyond full scale reads as "very large" instead of flipping sign.

### Packet 0x101 — Status, 1 Hz

| Channel | Offset | Size | Signed | Multiplier | Unit |
| --- | --- | --- | --- | --- | --- |
| Session time | 0 | 4 | no | 0.001 | s |
| Satellites | 4 | 1 | no | 1 | count (0xFF = unknown) |
| Fix quality | 5 | 1 | no | 1 | GGA quality code |
| Status flags | 6 | 1 | no | 1 | bit field, below |
| Device temperature | 7 | 2 | yes | 0.1 | degrees C |
| Session resets | 9 | 1 | no | 1 | count |

Status flag bits:

| Bit | Meaning |
| --- | --- |
| 0 | Inertial sensors have been zeroed |
| 1 | GNSS fix is valid and current |
| 2 | A zeroing capture is running right now |
| 3 | The last zeroing attempt was rejected |
| 4 | No GNSS fix in the last 3 seconds |

The temperature comes from the MPU-6050 die. It is not ambient temperature —
it runs several degrees warm — but it is a good proxy for how hot the box is
getting in the sun, and it is free.

Session time and the reset counter are the useful ones day to day: they confirm
from inside the app that a SET press actually landed, without looking at the
LED.

## What the device does with the filter

RaceChrono writes to the filter characteristic to say which packet IDs it wants
and how often. The firmware starts every connection in "deny all", so nothing is
published until the app has asked. If a channel does not appear, it is almost
always because the packet ID in the app does not match the tables above.

The firmware also enforces its own ceiling on the motion channel
(`KARTGPS_MOTION_PUBLISH_HZ`, 25 by default). Asking for a faster interval will
not exceed it; asking for a slower one will be honoured.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Device does not appear | Already connected to another phone; BLE allows one connection at a time |
| Connects, but no position | No sky view yet. A cold NEO-6M takes 30 s to a few minutes |
| Position works, no motion channels | Packet ID mismatch, or the channel was added to the wrong device |
| Motion data drifts or sits off zero | Zeroing was never taken or was rejected. Press SET with the kart still |
| Lateral and longitudinal are swapped | The box is not facing forwards. Set `KARTGPS_MOUNTING_YAW_DEGREES` and reflash |
| LED flashes twice per second, repeatedly | The MPU-6050 is not answering on I2C, or the last zeroing was rejected |
